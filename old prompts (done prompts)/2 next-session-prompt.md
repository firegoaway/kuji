# ЗАДАЧА 1. ЖЕСТЫ ВЬЮПОРТА (главный холст)

Матрица управления — реализовать строго:

| Ввод | Действие |
|---|---|
| Вращение колёсика (без модификаторов) | Зум приблизить/отдалить к точке под курсором. ПЛАВНО, мелкими шагами: за один «щелчок» колеса — плавная анимация ~5–8 микрошагов по ≈1,02–1,05 (QVariantAnimation/QTimeLine, 100–150 мс), без резких скачков. |
| Средняя кнопка мыши (нажать и вести) | Перемещение камеры XY (панорама). Курсор при этом — «захваченная рука» (ClosedHandCursor). |
| ЛКМ — клик | Выбор узла / ветви (текущая логика выбора и инспектор — сохранить). |
| ЛКМ — удержание на ПУСТОМ месте | Прямоугольное выделение (rubber band) в координатах сцены; выбор всех объектов в рамке. |
| ЛКМ — удержание на ОБЪЕКТЕ | Перетаскивание объекта: узел движется, входящие/исходящие связи перестраиваются на лету (Manhattan-пересчёт по новым позициям). |
| ПКМ | Контекстное меню (как сейчас). |

Требования к реализации:
- `setDragMode(NoDrag)`; все жесты — ручные обработчики `mousePressEvent/mouseMoveEvent/mouseReleaseEvent/wheelEvent` с tracked-состоянием (`IDLE / PANNING / RUBBER / MOVING_NODE`);
- рамка выделения — `QRubberBand` на вьюпорте с корректным маппингом в сцену при любом зуме;
- для перетаскивания узлов нужен рефакторинг сцены: вместо одного `TreeDiagramItem` сделать по элементу на узел (`NodeItem`: `ItemIsMovable | ItemSendsGeometryChanges`), `EdgeItem` и `HeaderItem`. Позиции — в модели: у `Node` появляется `manual_pos: (x, y) | None`. АвтолAYOUT (`compute_layout`) остаётся источником позиций «по умолчанию» (manual_pos=None); кнопка/действие «Авто-раскладка» сбрасывает manual_pos у всех и заново раскладывает. Пресеты и добавление барьеров по-прежнему раскладывают дерево автоматически;
- общий рендерер `render.py` переиспользуй для отрисовки NodeItem/EdgeItem (стиль не меняется, PDF-экспорт остаётся консистентным);
- колесо НЕ должно прокручивать вьюпорт (зум — единственная функция колеса; прокрутка — СКМ или ползунки окна документа из Задачи 2).

# ЗАДАЧА 2. ОКНО ДОКУМЕНТА «НАД ВЬЮПОРТОМ» (шапка-таблица уходит из вьюпорта)

Сейчас шапка эшелонов с пунктирной сеткой колонок встречает пользователя прямо в холсте (см. скриншот пользователя: «Инициирующее событие (ИС, Q_исх) | Выход вещества / образование горючей среды | Сработка ПАЗ / отсекающая арматура…»). Перенеси это табличное представление дерева в ОТДЕЛЬНОЕ окно/поле, размещённое НАД вьюпортом (вертикальный сплиттер: сверху документ, снизу рабочий вьюпорт; высоты тянутся мышью).

Содержимое окна документа: авто-раскладка дерева целиком — шапка эшелонов, колонки, узлы, связи, метки P, статусы (то, что сейчас рисует `draw_diagram`). Это «лист документа» — то, что уходит в PDF.

Управление в окне документа — НЕ как во вьюпорте:
- ползунок прокрутки СНИЗУ (влево-вправо) и ползунок СПРАВА (вверх-вниз) — стандартные QScrollBar, видимы всегда или AsNeeded;
- колесо мыши ВЕРТИКАЛЬНАЯ прокрутка (правый ползунок), Shift+колесо — ГОРИЗОНТАЛЬНАЯ (нижний ползунок);
- это поведение действует ТОЛЬКО когда курсор находится внутри окна документа; во вьюпорте и панелях колесо работает по своим правилам;
- в окне документа колесо НЕ зумит.

Реализация: отдельный `QGraphicsView` (режим NoDrag, `horizontalScrollBarPolicy/verticalScrollBarPolicy = ScrollBarAsNeeded`, `wheelEvent` переопределён: без Shift — `verticalScrollBar()`, с Shift — `horizontalScrollBar()`, событие принимается). Рекомендуется ОДНА QGraphicsScene на два представления (вьюпорт + окно документа): тогда правки узлов во вьюпорте мгновенно отражаются в документе. Зум вьюпорта не должен зумить окно документа (у каждого вида свой transform). Начальный масштаб окна документа — «вписать по ширине».
