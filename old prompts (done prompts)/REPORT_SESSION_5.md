## Что изменено по задачам

**Задача 7 – скролл во всех окнах.** Новый `eta/ui/scroll.py`: один
прикладной eventFilter на QApplication (Shift → горизонтальный ползунок
всех QAbstractScrollArea: таблицы, деревья, QScrollArea, QTextEdit);
зумящиеся вьюпорты (холст, окно документа) не затрагиваются; без
горизонтального диапазона – вертикальный запасной. Установка в main.py,
visual_qa_runner, gesture_test. Тест: сценарий 20 (синтетические
QWheelEvent на QTableWidget и QScrollArea инспектора). Грабли PySide:
сильная ссылка на Python-объект фильтра обязательна (GC обёртки молча
убивает переопределение eventFilter) – фикс в `install_scroll_wide`.

**Задача 6 – окно «База событий…».** Новый `eta/ui/kb_window.py`: кнопка в
верхнем тулбаре, немодальное окно, 6 вкладок (Инициирующие события ·
Ключевые события · Причины FTA · Логические элементы · Библиотека
значений · Пресеты). Просмотр + редактирование всех полей (Q/P/λ, source,
теги, подписи ветвей, формулы), добавление/удаление записей и групп
значений; «Сохранить» – атомарная перезапись knowledge_base.json
(tempfile + os.replace) и перезагрузка KnowledgeBase на лету (сигнал
kb_reloaded → сцены/статус без перезапуска); «Перечитать из файла»
отбрасывает несохранённые правки. DnD карточек на холст сохранён
(EventCard). Палитра из левой панели главного окна убрана. KB-загрузчик
(`kb.py`) получил save()/reload()/_reindex(). Тест: сценарий 21
(сохранение в копию файла, перезагрузка, «Перечитать»).

**Задача 1 – сценарии-цепочки (главная).** `model.py`: SplitSpec.kind
(barrier|physical) + pfd; Node.terminal_safe; add_split со вставкой

Рендер: бейдж «PFD = … · F_вых = F_вх·PFD» на узле-барьере, метки
«PFD = …»/«1−PFD = …», компактные терминалы (COMPACT_MAX_W); в PDF –
легенда и заголовки таблицы под цепочки. Сериализация: kind/terminal_safe
в формате, НОРМАЛИЗАЦИЯ форматов 1/2 при загрузке (сработавшая ветвь
защиты сворачивается в терминал, ΣQ сохраняется, идемпотентно). Тесты:

**Задача 2 – иерархия объекта.** Новый `eta/core/objects.py` (ObjectTree,

**Задача 3 – педальки свойств.** Новая секция БЗ `property_modifiers`
(17 записей, каждая с formula/source/confidence: normative /
normative-anchored / engineering-estimate). Новый `eta/core/generator.py`:
λ_итог = λ_баз·∏k_i (износ 2–5, виброконтроль 0,7, герметичность 0,5 –
engineering; якоря – k_кпз=0,16, k_бд=0,07 Методики 533 прил. 6); SIL 1–4
(ГОСТ Р МЭК 61508-1 табл. 2, по умолчанию верхняя граница) с голосованием
1oo2 → PFD², 2oo3 → 3P²−2P³ (61508-6); PFD_avg ≈ λ_DU·T_тест/2 (итог
PFD = max(SIL-голосование, PFD_avg), консервативно); вентиляция
P_ост = 1/(A·T+1) (якорь К=А·Т+1, ГОСТ Р 12.3.047-98 (А.13)); категория
среды/расхода управляет физическими ветвями (табл. П2.1); «Негорючая» и
взрывозащищённое исполнение – блокировщики; T_раб ≥ T_самовоспл → P = 1
(п. 3 Прил. № 2). Инспектор: редакторы педалек/полей для оборудования и
контейнеров, поле «A, ч⁻¹» появляется при включённой вентиляции
(Помещение/Участок/Оборудование), каскад: наследование вниз, локальное
переопределение сверху; правка → регенерация дерева. Тесты: smoke 15–16,
сценарий 23.

**Задача 4 – молниезащита.** Педалька в свойствах Здания (уровень
I/II/III/IV → η = 0,98/0,95/0,90/0,80 – СО 153-34.21.122-2003 табл. 2.2)
+ размеры S/L/H. Q_пораж = N_у.м·(1−η), N_у.м = (S+6H)(L+6H)·n_у·10⁻⁶
(ГОСТ 12.1.004-91 прил. 3 п. 3.1.3); причина c-iz-lightning получает
k_scale (FtaNode.k_scale, сериализуется), Q фазы ИЗ пересчитывается.
Тест: smoke 17 (η-таблица, масштаб, round-trip).

**Задача 5 – домино.** Новый `eta/core/domino.py`: связи
«финальное событие → мишень» (маркер-мишень – элемент иерархии,
перетащенный на холст); ЛКМ-перетаскивание hazard-листа на маркер создаёт
связь (узел возвращается на место); ПКМ – «Условия перехода…»
(P_перехода, подстановка P = Φ(Pr−5) из пробита, пороги с источниками),
удаление. Каскадная маршрутизация: абстрактная «Территория» не горит –
внешнее воздействие (c-gs-external-fire, Q = Q_сценария·P) автоматически
пробрасывается в фазу ГС каждого дерева дочернего оборудования; проброски
помечены «domino:» и пересоздаются идемпотентно. Отрисовка: пунктир
ACCENT, слой Z_DOMINO; ΣQ каскадов в статус-баре. Сериализация в формат 3.
Probit-пороги – Методика 533 прил. 4 + прил. 3 п. 43 + Cozzani 2006
(engineering) – в БЗ (pm-domino) и диалоге. Тесты: smoke 18, сценарий 24.

## Дизайн-заметка: математика цепочек (Задача 1)

Семантика заменена с «бинарного дерева 2^n» на «цепочку с барьерными
узлами и редкими физическими развилками»:

1. Дерево осталось бинарным по структуре (совместимость рендера, PDF,
   сериализации), но развилки получили тип:
   - barrier (защиты: ПАЗ, АУПТ, дренаж, вентиляция, датчики, ПАЗ-SIL):
     отказная ветвь (PFD = 1 − P) продолжает ЦЕПОЧКУ, сработавшая
     (1 − PFD) – короткий безопасный терминал «Прекращение аварии»
     той же цепочки; число физических сценариев НЕ растёт;
   - physical (воспламенения, тип горения): обе ветви – самостоятельные
     физические исходы, Σ условных вероятностей = 1 (табл. П2.1).
2. Инварианты сохранены и проверены тестами: на каждом узле ΣP = 1
   (PFD + (1−PFD) = 1); ΣQ ВСЕХ терминальных исходов, включая безопасные
   прекращения, = Q_центра (благодаря PFD + (1−PFD) = 1 барьер не теряет
   и не создаёт частоту); Q_центра = Q_ГС·Q_ИЗ (FTA не изменилась).
3. Таблица «Сценарии» содержит только физические цепочки
   (ИС → … → поражающий фактор / «Без воспламенения»); прекращения
   показываются сводкой (количество, ΣQ_прекр) и инвариантом ΣQ.
4. Вставка защиты в середину цепочки: старая развилка переносится на
   отказную ветвь – хронология эшелонов сохраняется, физика не меняется,
   пользователь настраивает топологию цепочки педальками/перетаскиванием.
5. Нормализация старых файлов: для каждой развилки-защиты «сработавшая»
   ветвь с поддеревом сворачивается в один терминал с Q = Q_узла·(1−PFD);
   сумма листьев старого поддерева равна этой величине по построению
   старой семантики (ΣP = 1), поэтому ΣQ терминалов сохраняется точно;
   повторная загрузка ничего не меняет (идемпотентность).
6. PFD-модификаторы из свойств (SIL/voting/T_тест/вентиляция) порождают
   те же барьерные узлы генератором: F_выход = F_вход · PFD_барьера,
   произведение PFD вдоль цепочки даёт Q_j сценария; λ-модификаторы
   множат только Q_исх (λ_итог = λ_баз·∏k_i) – топологию не меняют.

## Особенности среды (важно для следующих сессий)

- Песочница DSH запрещает запись в HKCU дочерним процессам: QSettings
  NativeFormat даёт AccessError. Тесты переведены на герметичные ini
  (qa_artifacts/_qsettings, формат по умолчанию IniFormat);
  `migrate_qsettings` уважает формат по умолчанию. Приложение вне
  песочницы работает с реестром как раньше.
- Грабли PySide (уже в коде с комментариями): GC обёртки фильтра
  событий; org/app-конструктор QSettings игнорирует defaultFormat.
