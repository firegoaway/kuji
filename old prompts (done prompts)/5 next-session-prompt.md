## 0. СОСТОЯНИЕ ПРОЕКТА (фиксация на 07.11.2026, вечер, после сессии №4)

Реализовано и зелёное (всё из сессий №1–4):

- **Гибрид «галстук-бабочка»**: слева дерево отказов (FTA, уровни −5…−1), в центре событие уровня 0 «ГС + ИЗ», справа дерево событий (ETA, уровни 1–5). FTA: ДВЕ фазовые цепи — фаза ГС (горючая среда, слот −5…−3) и фаза ИЗ (источник зажигания, слот −2…−1), сходятся конъюнкцией (логическое И) в центр: Q_центра = Q_ГС · Q_ИЗ. Порядок фаз «ГС → ИЗ» / «ИЗ → ГС» меняется (без промежуточных элементов в глубокой фазе).
- **Терминология нормативная** (см. раздел «Стилевые правила»): «ключевое событие» (не «событие-барьер»), «логический элемент И/ИЛИ» (не «гейт»), «вершинное событие фазы» (не «верхний гейт»), «промежуточный логический элемент» (не «вложенный гейт»). Слов «гейт»/«барьер» в UI-строках НЕТ.
- **Математика**: И → Q = ∏Q_i; ИЛИ → Q = 1 − ∏(1−Q_i); ΣP = 1 на каждой развилке ETA; ΣQ листьев = Q_центра; порог отсечения опционален (None = «Нет»).
- **БЗ** (`knowledge_base.json`): эшелоны −5…5; 72 инициирующих события; 37 ключевых событий (ETA); 30 причин FTA с source у каждой (14 на −5, 6 на −4, 10 на −2; есть удельные м⁻¹·год⁻¹ с `freq_mode: per_meter` и `length_m`); 2 шаблона логических элементов (`fta-gate-and/or`); библиотека значений; 3 пресета; `cause_notes` (оговорки ИЛИ-аппроксимации, per-m, категории без данных НЕ выдуманы).
- **UI**: левая вертикальная панель инструментов у вьюпорта (зум±, «Показать всё» Alt+A, режимы обзора «липкий/свободный», мусорка); палитра-аккордеон слева (группы init, lvl-5…lvl-1 — в −3/−1 карточки логических элементов, lvl1…5); правая панель — вкладки «Свойства события» и «Сценарии»; окно документа над вьюпортом; верхний тулбар (Новый/Открыть…/Сохранить…/Авто-раскладка/порог/Экспорт PDF…).
- **Жесты**: колесо — плавный зум к курсору (якорь вручную), СКМ — панорама, Shift+колесо в окне документа — горизонталь; тач: пинч-зум (`apply_pinch`), QScroller-панорама, тап/двойной тап = клик; режимы обзора sticky/free (`ui/viewport_mode`, свободный = мир ±5000 px); Delete удаляет выделенные поддеревья (guard на поля ввода); Alt+A.

# ЗАДАЧА 1. СЦЕНАРИИ-ЦЕПОЧКИ: ОТКАЗ ОТ КОМБИНАТОРНОГО ВЗРЫВА ВЕТВЕЙ

Главная задача сессии. Сейчас каждое ключевое событие порождает развилку «сработало (P) / не сработало (1−P)», и листья дерева = отдельные «сценарии» — их 2^n, что и даёт комбинаторный взрыв. Новая семантика:

- **Один сценарий = одна физическая цепочка** развития аварии: конкретное свершившееся событие от инициирующего отказа до конечного поражающего фактора (Взрыв ТВС / Факельное горение / Пожар пролива / Без воспламенения и т.п.).
- **Ключевые события-защиты (ПАЗ, отсечные клапаны, АУПТ, сигнализация, дренаж…) НЕ порождают новых самостоятельных сценариев.** Они встраиваются в текущую цепочку как узлы-модификаторы вероятности прохождения волны аварии дальше:
  - `F_выход = F_вход · PFD`, где PFD — вероятность отказа барьера на запрос (несрабатывания защиты);
  - альтернативный выход узла («защита сработала», вероятность `1 − PFD`) — терминальный безопасный исход «Прекращение/лимитация аварии» той же цепочки, а НЕ новый сценарий.
- **Физические развилки** (тип горения по категории среды: ТВС/факел/пролив/нет воспламенения) остаются ветвлениями с условными вероятностями из БЗ (табл. П2.1 Методики для воспламенений; для ГГ/ЛВЖ/ГЖ/негорючей — набор допустимых ветвей см. Задачу 3), Σ условных вероятностей физической развилки = 1.
- **Инварианты (проверить тестами)**: на каждом узле ΣP = 1 (PFD + (1−PFD) = 1; физическая развилка Σ = 1); ΣQ всех терминальных исходов (включая безопасные прекращения) = Q_центра; в таблице «Сценарии» — только физические поражающие исходы, число строк не растёт от числа защит.
- **Таблица «Сценарии»**: №, физическая цепочка (ИС → … → поражающий фактор), Q_j, статус. Сводка: Q_ГС, Q_ИЗ, Q центра, Σ Q_j (в расчете ОФП).
- **Отображение на холсте**: узел-барьер цепочки — узел с бейджем «PFD = …» и формулой F_выход = F_вход·PFD; выход «сработала» — короткая ветвь «Прекращение аварии» (safe-терминал, серый/зелёный цвет по статусу). ETA-сторона перестаёт быть бинарным деревом 2^n — становится цепочкой с барьерными узлами и редкими физическими развилками.
- **Совместимость**: старые файлы формата 1/2 открываются — при загрузке НОРМАЛИЗУЙ старое дерево в цепочки: для каждого ключевого события оставить отказную ветвь продолжением цепочки (умножая на PFD = 1 − p_success), а «сработавшую» ветвь свернуть в safe-терминал (вложенные поддеревья сработавшей ветви отбрасываются с сохранением ΣQ — их Q переходит в safe-терминал). Тест: round-trip старого файла, ΣQ терминалов сохраняется.
- **Сериализация**: формат 3 (см. ниже), либо расширение формата 2 — реши сам, но читаемость 1/2 обязательна и отрази в отчёте.
- Правая FTA-сторона (фазы ГС/ИЗ, логические элементы) НЕ меняется. Пересчёт Q_центра прежний.

# ЗАДАЧА 3. ПРАВАЯ ПАНЕЛЬ: ВКЛАДКА «СВОЙСТВА» И ГЕНЕРАЦИЯ ДЕРЕВА

Локальное дерево конкретного оборудования меняется ТОЛЬКО через свойства в правой панели (ручное DnD барьеров на холсте остаётся как дополнительный инструмент, но педальки — главный путь). Вкладка «Свойства оборудования» появляется ТОЛЬКО при выделении объекта класса «Оборудование» в иерархии; для Помещений/Отсеков — свои свойства локализации (предел огнестойкости преград, общеобменная вентиляция с кратностью A, площадь); для Зданий — степень огнестойкости, этажность, педалька «Молниезащита» (Задача 4).

**Свойства делятся на два типа**: (а) модификаторы базовой частоты инициирующего события λ — меняют только числа; (б) барьеры безопасности — добавляют/изменяют узлы цепочки (PFD-модификаторы по Задаче 1) или отсекают ветви.

### 3.1. Чекбоксы («педальки»)

| Категория | Педалька | Эффект | Тип |
|---|---|---|---|
| Локализация | Аварийный дренаж / слив | Быстрое удаление горючей жидкости из зоны аварии | барьер (сокращение длительности истечения) |
| Локализация | Вытяжная / аварийная вентиляция | Снижает вероятность образования взрывоопасной газовоздушной смеси; при включении открывает поле «Кратность воздухообмена A, ч⁻¹» | барьер, P_ВОК = f(A) |
| Обнаружение и тушение | Датчики утечки / газоанализаторы | Барьер раннего обнаружения до воспламенения | барьер |
| Обнаружение и тушение | Контроль температуры / вибрации | Снижает λ внезапного катастрофического отказа | λ-модификатор, k < 1 |
| Обнаружение и тушение | Локальное пожаротушение (АУПТ) | Ликвидация пожара на начальной стадии (D_АУП = 0,9 → PFD = 0,1; табл. П2.2) | барьер |
| Обнаружение и тушение | Водяное орошение / охлаждение | Предотвращает разрушения от теплового излучения | барьер |
| Надёжность | Наличие резерва (горячий/холодный) | Логика отказа «И»: P = P₁·P₂ + поле «Степень резервирования» | voting-перестройка |
| Надёжность | Износ (превышен срок службы) | Повышающий коэффициент к λ | λ-модификатор, k > 1 |
| Прочее | Герметичное исполнение / Антикоррозийная защита | Снижение λ | λ-модификатор |
| Прочее | Взрывозащищённое исполнение | Отсекает/сереет ветви воспламенения и взрыва | блокировщик сценариев |

### 3.2. Выпадающие списки и числовые поля

- **Уровень полноты безопасности SIL 1–4** — базовый PFD защитных реле/клапанов ПАЗ (МЭК 61508, низкая частота запросов): SIL 1: 10⁻²…10⁻¹; SIL 2: 10⁻³…10⁻²; SIL 3: 10⁻⁴…10⁻³; SIL 4: 10⁻⁵…10⁻⁴. По умолчанию — верхняя (консервативная) граница диапазона, значение редактируемо.
- **Категория взрывопожароопасности среды (ГГ, ЛВЖ, ГЖ, негорючая)** — определяет НАЛИЧИЕ ветвей «Взрыв ТВС», «Факельное горение», «Пожар пролива» (генератор физической развилки Задачи 1); «негорючая» — блокировщик ветвей горения.
- **Рабочее давление (МПа) и температура (°C)** — влияют на расход истечения при разгерметизации и вероятность самовоспламенения (коэффициенты — research с source, см. ниже).
- **Степень резервирования (1oo1, 1oo2, 2oo3)** — перестраивает логику срабатывания защитной автоматики: 1oo2 → PFD_сист = PFD²; 2oo3 → PFD_сист = 3·PFD² − 2·PFD³ (формулы voting зафиксируй в коде/доках/тестах).
- **Периодичность ТО и проверок защит T_тест** — готовность барьера: `PFD_avg ≈ λ_DU · T_тест / 2`, где λ_DU — интенсивность опасных необнаруживаемых отказов защиты (значения λ_DU — research с source).

### 3.3. Связь свойств с перестроением дерева

1. **Модификаторы входа (λ)**: герметичное исполнение, антикоррозийная защита, износ, виброконтроль — НЕ меняют топологию, умножают базовую частоту: `λ_итог = λ_баз · ∏ k_i`.
2. **Генераторы ветвей**: каждая педалька-защита (дренаж, вентиляция, датчики утечки, АУПТ, орошение, отсечной клапан, реле) включает/отключает соответствующий барьерный узел цепочки на холсте (Задача 1).
3. **Блокировщики**: «Взрывозащищённое исполнение» и «Негорючая среда» полностью отсекают (или окрашивают в неактивный серый CUTOFF) ветви воспламенения и взрыва.
- Все числовые значения k_i, PFD барьеров, λ_DU, зависимость P_ВОК от A — **research** (Методика № 533, ГОСТ 12.1.004-91 прил. 3, ГОСТ Р 12.3.047-98 (прил. Э), IEC 61508, интернет). НЕ выдумывать: каждое значение с source в БЗ (`property_modifiers` — новая секция: id, категория, тип, значение, формула, source). Дежурную исследовательскую задачу делегируй сабагенту параллельно с кодом.
- Аварийная вентиляция: педалька доступна для «Помещения», «Участка» И «Оборудования»; при включении появляется/исчезает числовое поле «Кратность воздухообмена A, ч⁻¹» (единица — час в минус первой).

- Педалька «Молниезащита» в свойствах «Здания»: при включении частота поражения дочерних объектов снижается на надёжность защиты: `Q_пораж = N_у.м · (1 − η_МЗ)`; влияет на фазу ИЗ деревьев оборудования внутри здания (ветвь c-iz-lightning). Формулу, значения η_МЗ по категориям защиты — в БЗ с source.

# ЗАДАЧА 5. КАСКАДНЫЕ СЦЕНАРИИ (ЭФФЕКТ ДОМИНО / ПЕРЕХОД ПОЖАРА)

- Если рядом несколько территорий/зданий (дрейф облака, тепловое излучение), пользователь моделирует переход аварии между ними.
- **Механика на холсте**: пользователь перетаскивает элемент иерархии («Территория 2» / «Здание 2») на холст как ноду-мишень. ЛКМ — тянет связь от финального события (свершившегося сценария: пожар/взрыв/излучение/дрейф облака) первой территории ко второй. ПКМ на связи — условия/свойства перехода (вероятность P_перехода, порог дозы/давления; probit-модели — research с source: Методика № 533 приложения по эффекту домино, ГОСТ Р 12.3.047-98; при отсутствии — явная инженерная посылка с source).
- **Правило каскадной маршрутизации**: абстрактная «Территория» гореть не может — при соединении выхода сценария «Территории 1» со входом «Территории 2» система автоматически пробрасывает инициирующую ветвь внешнего воздействия на ДОЧЕРНИЕ элементы «Территории 2» (её здания/наружные установки), если они есть в иерархии: у них порождаются инициирующие события «внешнее воздействие» с частотой `Q_сценария1 · P_перехода` (связка с `init-fireball-ext` / `c-gs-external-fire` из БЗ).
- Отображение: межобъектные связи домино — пунктир EDGE/ACCENT поверх сцены между деревьями (отдельный z-слой или класс item); в сводке — суммарная частота каскадов.
